# CodeWake · 醒码：全部熄屏与内屏亮度恢复

本文行为与回归场景记录自 Lidless AI 0.2.15 / build 19，保留为历史交接依据。CodeWake 改名不改变这些功能；历史自动验证记录不等于新版本实机验收。

## 行为

- 全部熄屏只关闭显示器，不新增或释放任务、手动或计时防睡眠来源，也不修改“保持屏幕常亮”的持久设置。
- 内屏在线时，先恢复原亮度，再发送一次系统显示器睡眠请求。
- 内屏已合盖且离线时，允许先熄灭所有在线外屏；原亮度恢复记录和恢复进程继续保留，开盖后自动恢复。
- 内屏亮度故障、损坏的恢复记录、无法确认的上盖/显示器状态或不可用的恢复进程，不属于可安全延后的情况。

## 安全边界

全屏准备接口区分 `ready`、`deferredBuiltInRecovery` 和 `blocked(reason)`，不改变原有 `restore(Bool)` 对退出和正常休眠释放的含义。

安全延后必须同时具备：有效且处于恢复阶段的原记录、已认证并存活的恢复子进程、子进程对同一份记录的离线确认，以及即时确认的“上盖关闭、无在线内屏、至少一个在线外屏”。文件存在不等于记录有效；新建内屏熄灭的 capability 不等于恢复状态。

显示器集合使用完整 ID 和内外屏标记，上盖状态单独读取；读取期间变化或信息不完整时不放行。点击开始计时，保留 1.5 秒延迟。准备和延迟期间开盖、换屏或状态不明会取消未发出的操作，发出前再次检查。命令发出后不自动重发，用户唤醒后旧回调不能再次熄屏。

恢复原因变化时沿用现有协议重新上报，同原因不重复发送。实际亮度故障不能被随后合盖覆盖；只有确认恢复或用户已调亮，才完成恢复并清除记录。取消全屏操作不能连带停止恢复。

## 回归验收

自动验证包括：完整显示器与上盖采样、双外屏安全延后、准备取消、错过通知、同数量换屏、迟到回调、命令和确认超时、恢复原因变化、恢复记录损坏或被替换、子进程退出、用户调亮保留，以及双语提示。

实机验收必须在用户允许的时间窗口进行，不能以自动测试代替：

1. 在内屏单独使用且后台任务工作时点“内屏熄灭”，合盖后连接两台外屏。
2. 保持合盖点“全部熄屏”，确认两台外屏均熄灭，后台任务和原防睡眠状态继续。
3. 开盖，确认内屏恢复；移动鼠标恢复显示，确认不会再次被旧操作熄灭。
4. 重复测试延迟期间开盖、插拔外屏，以及恢复期间手动调高亮度。

## 安装与回退

历史 build 19 交付时未自动退出或替换正在运行的版本。CodeWake 0.2.17 的本机更新会先备份工作区与已安装应用，再安装到 `/Applications/CodeWake.app`，并保留旧应用供回退。旧 Bundle ID、辅助程序身份、hooks 和恢复记录路径沿用，以继承现有设置。

本次 GitHub 开源交付仅发布源码，不发布安装包。新版本交付结果应分别注明自动验证、本机签名安装和实机验收；未完成的合盖、双击熄屏及亮度恢复检查必须明确列出，不能引用历史结果作为已完成。

Developer ID 签名只代表本地签名验证；未经 Apple 公证的包不得描述为已公证的公开发行版本。
