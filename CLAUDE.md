# CodeWake — contributor & agent notes

## Always verify locally before opening a PR

**Local verification is the gate.** Run the same checks CI would and make sure
they are green before creating any PR or publishing a source snapshot.

```bash
# Regenerate the Xcode project from project.yml (the source of truth —
# `CodeWake.xcodeproj` is gitignored) and run the unit tests.
xcodegen generate
xcodebuild test -project 'CodeWake.xcodeproj' -scheme CodeWake-CI \
  -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO LIDLESS_DEVELOPMENT_TEAM=
```

`| xcbeautify` is optional (prettier output); the run must end in
`** TEST SUCCEEDED **`.

For app/UI changes, also confirm the app builds:

```bash
xcodebuild build -project 'CodeWake.xcodeproj' -scheme CodeWake \
  -destination 'generic/platform=macOS' -configuration Debug \
  CODE_SIGNING_ALLOWED=NO LIDLESS_DEVELOPMENT_TEAM=
```

Only open the PR once these pass locally. GitHub Actions runs the same
`CodeWake-CI` scheme; a local passing run does not establish real-device
acceptance or a signed/notarized distribution.

## Project basics

- **`project.yml` is the source of truth.** `CodeWake.xcodeproj` is generated by
  `xcodegen generate` and gitignored — never hand-edit the project; edit
  `project.yml` and regenerate.
- **Debug builds use bundle id `com.kenny.lidlessai.dev`** so a dev build
  coexists with the released app (separate UserDefaults, login item, and
  privileged helper). Release uses `com.kenny.lidlessai`.
- **Signing identity is never committed.** Pass
  `LIDLESS_DEVELOPMENT_TEAM=<YOUR_TEAM_ID>` locally. The helper rejects every
  XPC client when a real Team ID was not injected.
- **Release pipeline:** `scripts/release.sh` creates a signed, notarized app and
  DMG only. CodeWake intentionally has no inherited Sparkle feed or upstream
  publishing step. The public repository is
  `https://github.com/zeyanlikiny-jpg/codewake` and publishes source code only;
  installation packages and signing material are excluded.
- **Keep upgrade identities stable.** `com.kenny.lidlessai`, the `LidlessHelper`,
  `LidlessAIHookBridge`, and `LidlessDisplayWatchdog` tool names,
  `~/Library/Application Support/Lidless AI/` paths, and
  `LIDLESS_DEVELOPMENT_TEAM` remain for preferences, hooks, helper authorization,
  and recovery compatibility. User-facing English uses CodeWake; Chinese uses
  CodeWake · 醒码.
